# Modifier

Minecraft Paper 用プラグイン。

| モジュール | 中身 |
| --- | --- |
| `plugin/` | Paper プラグイン `Modifier` |
| `e2e/` | ヘッドレスクライアントによる通し検証 |
| `pack/` | リソースパック (アイコン・効果音) |

開発環境は [`world_is_also_hardcore`](../world_is_also_hardcore) と同じ構成
(JDK 25 / Gradle 9 / `flake.nix` の Paper テストサーバー) にしてある。
ただしワールドリセットのような再起動を要する仕組みは無いので、`mstore` には依存しない。

## プラグイン設定 (`plugins/Modifier/config.yml`)

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `enabled` | `true` | `false` なら何もしない |
| `message-prefix` | `[Modifier] ` | コマンドの返答に付ける接頭辞 (MiniMessage 形式) |
| `selection.title` | `モディファイアを選択` | 選択画面のタイトル (MiniMessage 形式) |
| `selection.choice-count` | `3` | 提示する選択肢の数 (1〜3) |

## コマンド

`/modifier` — 別名 `/m`

### 引数なし: 自分のモディファイアを見る

権限 `modifier.use` (既定: 全員)。実行した本人のチャットに、選んでいるモディファイアの
名前とその効果の説明を返す。

```
[Modifier] 選択中: 肥満
  移動速度が下がる
  ノックバックを受けにくい
```

まだ選んでいなければその旨だけを返す。選んだ id が登録から消えている場合 (ビルドや
config を差し替えたとき) は、その id を添えて知らせる。

### サブコマンド: 管理用

権限 `modifier.admin` (既定: OP)。`/m status` のように別名からも使える。

- `status` — バージョン・`enabled`・登録数・自分の選択状況・パック配信・各アイコンと重み
- `select` — 選択画面を開く (動作確認用)
- `reload` — `config.yml` を再読み込み

## 開発

### 遊ぶサーバーを立てる

**`wiah` / `death_counter` と一緒に動かす本番相当のサーバーは、親ディレクトリの `start.sh` で起動する。**

```console
$ cd .. && ./start.sh
```

3つのプラグインと mstore をビルドし、`Modifier/run/plugins` へ配置してから
mstore 経由で起動する。mstore が Paper を子プロセスとして抱え、同じプロセスで
KV ストア (`http://127.0.0.1:8080`) も動かすので、これ1つで両方が上がる。

**起動のたびに必ずビルドし直す。**「直したのに古い jar のままだった」を踏まないため。
急ぐときは `--no-build`。Ctrl-C でワールドを保存してから止まる。

すでに起動していると、PID とポートの両方を見て**何もせずに降りる**。動作中に jar を
差し替えるとクラスの遅延読み込みが壊れるため。

### プラグイン単体で試す

```console
$ nix develop
$ modifier-dev             # ビルド → ./run/plugins へ配置 → テストサーバー起動
```

`modifier-dev` は Modifier だけを載せた素の Paper を立てる (mstore も wiah も無し)。

個別に動かす場合:

```console
$ gradle :plugin:build
$ deploy-plugin            # ビルド成果物を ./run/plugins へコピー
$ paper-server             # ./run でテストサーバーを起動
$ paper-jar 1.21.4         # jar を取得してパスだけ表示
```

`paper-jar` は PaperMC の v3 API から最新の安定ビルドを取得し、SHA256 を検証する。
バージョンを固定したい場合は引数で指定する (`modifier-dev 1.21.4` のように渡せる)。

> `paper-server` / `modifier-dev` はローカル検証専用なので `./run/eula.txt` に
> `eula=true` を書く。同意したくない場合は使わないこと。

## モディファイア

プレイヤーに効果を与える「モディファイア」を、ワールドへの新規参加時に3択から選ばせる。

| クラス | 役割 |
| --- | --- |
| `Modifier` | モディファイアのメタ情報。効果の適用フックは今後ここに足す |
| `ModifierRegistry` | 登録一覧と、そこからの抽選 |
| `SelectionStore` | 選択の保存 (プレイヤーの PDC) と「選択画面が要るか」の判定。よくばりの中身もここ |
| `SelectionGuard` | 選んでいる間、敵モブに殺されないよう無敵にする |
| `ModifierBundle` | 複数のモディファイアを 1 つとして扱う。よくばりが使う |
| `SelectionLayout` | 選択画面のスロット配置 |
| `SelectionMenu` | 選択画面そのもの。`InventoryHolder` を兼ねる |
| `SelectionService` | 選択画面の提示。提示した選択肢をプレイヤーごとに保持する |
| `SelectionListener` | 参加時の表示と、画面内の操作の封じ込め。確定時に道具を配る |
| `StartingItems` | 選んだときに受け取る道具。素材と個数で持ち、確定時に `ItemStack` にして渡す |
| `WelcomeGift` | どれを選んでももらえるウェルカムギフト (ベッド・パン・木材・石炭、5% で金のリンゴ) |
| `NameTagDisplay` | 選んでいるモディファイア名をネームタグの下段に出す (スコアボードの `below_name`) |

### 選択画面を出す条件

参加時に以下のいずれかなら出す。

- モディファイアが未選択
- 選択済みだが、**選んだときとは別の主ワールド**になっている

選択は選んだ時点の主ワールド UID と一緒にプレイヤーの PDC へ保存する。PDC は
`world/playerdata` に入るのでワールドを作り直せば選択も消えるが、それとは独立に
UID でも判定することで、プレイヤーデータが残る構成でも選び直しになる。

### アイコン

土台のアイテムに `minecraft:item_model` を載せて差し替える。パックを適用していない
クライアントには土台アイテムの見た目で出るので、パック無しでも成立する。

元のアイコンは `pack/assets/modifier/textures/item/<id>.png` に 128x128 で置く。24種すべて
揃っている (`PackAssetsTest` の `PENDING_ICONS` は空)。元絵は `../tx/` の 1254x1254 で、
面積平均で 128x128 に縮めて置く。

> 128x128 にしてあるのは、GUI のスロットが 16x16 GUI ピクセルで、GUI Scale 4 なら
> 実画面 64px、Scale 6 でも 96px にしかならないため。これ以上上げてもアトラスが
> 膨らむだけで見た目は変わらない。

### 受け取る道具

道具をもらえるものは、`Modifier#startingItems()` に素材と個数 (`StartingItems.Item`) を返す。
**選択を確定した瞬間に一度だけ**持ち物へ入れ (`SelectionListener#choose` → `StartingItems#give`)、
入り切らなければ足元に落とす。参加やリスポーンでは配り直さない。`/m select` で選び直せば、
そのたびにもらえる (管理用なので気にしない)。

選択画面の説明と `/m` の出力には「受け取る道具: 盾」のような行が自動で添えられる。
名前は翻訳キーで組むので、クライアントの言語で出る。

### ウェルカムギフト

どれを選んでも、確定時に `WelcomeGift` が **赤いベッド・パン 4・オークの木材 16・石炭 16** を配る。
加えて **5% でエンチャントされた金のリンゴ**。当たった本人にだけ知らせる。配り方はモディファイア固有の
道具と同じ。

**そのワールドで初めて選んだときだけ。** 渡したワールドの UID を PDC (`modifier:welcomed`) に残し、
`/m select` で選び直しても二度目は配らない。ワールドを作り直せば UID が変わるのでまた受け取れる。

### 出現の重み

3択は**重み付きの抽選**で、重みは `Modifier#weight()` が返す。合計を 100 に揃えてあるので、
上の表の数字がそのまま相対的な出やすさになる (`ModifierRegistryTest` が合計を見張っている)。

重みは**強さではなく「引いた人以外への影響」**で決めてある。強さで重み付けすると、
弱いものばかり出て選択が作業になるため。

24種になった時点で段ごとの数字を縮めて 100 に収め直した。段の順序と、
死を打ち消すものが標準 (`DEFAULT_WEIGHT` = 8) より明確に低いことは変えていない。

| 段 | 重み | 何を見ているか |
| --- | ---: | --- |
| 極レア | 1〜2 | **ワールドの生死に触る** — 無キャ・冷笑・死神ルーレット・クリーパー保険。それと、鉱石が増えるのが強すぎる採掘師 |
| 低め | 4 | 単独では腐る、純粋な下方修正しかない、または周りを巻き込む — ヒーラー・食中毒・リーダー・歌姫・不眠症・アホ・ピエロ・地雷系・よくばり (死を打ち消すものを引きうる) |
| 標準 | 5 | 引いて嬉しく、他人に迷惑をかけない — スウィフトネスブーツ・農奴・ドパガキ・黒の剣士・シェフ・フィッシャーズ・熱血お肉屋さん |
| やや高め | 6 | 取引が明快で、受動的に強くならない — シールドバッシュ・デブ |
| 最多 | 8 | **なにもしない** — 後悔。引くたびに後悔できるよう、一番よく出す |

死を打ち消す3種を低くしているのは、**wiah と組み合わせると個人の効果ではなくなる**ため。
打ち消された死では `PlayerDeathEvent` が生まれず、ワールドリセットも走らない
(`WorldResetE2eTest` で実証済み)。つまりこれらは「予備の1回」ではなく
**「ワールドがもう一度だけ死を許される」**という、パーティ全体に効く効果になる。

3つ引くぶん、実際の出現率は重みの比より高くなる。

| | 重み | 3択に出る確率 | 均等なら |
| --- | ---: | ---: | ---: |
| 無キャ | 1 | 3.1% | 12.5% |
| 冷笑 / 死神ルーレット / クリーパー保険 / 採掘師 | 2 | 6.2% | 12.5% |
| 低めの9種 | 4 | 12.1% | 12.5% |
| 標準の7種 | 5 | 15.0% | 12.5% |
| シールドバッシュ / デブ | 6 | 17.7% | 12.5% |
| 後悔 | 8 | 23.1% | 12.5% |

> **重みは出現率しか動かさない。** プレイヤーは3択から1つ選ぶので、実際に付く確率は
> 「出現率 × 選ばれる率」になる。とくに無キャは説明文が「なにも起こらない気がする。」
> なので、謎枠として逆に選ばれる可能性がある。
>
> また、**稀にすることは分かりにくさを解決しない**。20回に1回しか起きず誰にも説明され
> ない挙動は、プレイヤーからはバグに見える。無キャについては頻度とは別に、発動が何らか
> の形で分かるようにするかどうかが未決のまま残っている。

効果は2種類に分けて実装してある。

- **常時** — `Modifier#apply`/`remove` で attribute を付け外しする。`addTransientModifier` を
  使うのでプレイヤーのデータには保存されず、プラグインを外した後に効果が残らない。
  何度呼ばれても二重にかからないよう、固定のキーで remove してから add する。
- **状況発動** — `onDamaged` / `onDealtDamage` / `onKill` / `onKillDrops` / `onBlockDrops` /
  `onConsume` / `onPotionEffect` / `onProjectileHit` / `onFish` / `onItemDrop` / `onCraftPrepared` /
  `onInventoryClick` / `onInteract` / `onDeath` / `interceptDeath`
  などのフックへ、`ModifierEffects` が選択中の
  モディファイアの分だけ配る。

イベント優先度は4段構え: NORMAL (被弾側の加工) → HIGH (攻撃側の反応、落とし物の加工) →
HIGHEST (致死判定) → MONITOR (反射・キル反応など、確定後だけの反応)。
落とし物は `onKillDrops` (HIGH) で書き換え、`onKill` (MONITOR) は確定後の反応にだけ使う。
「死がなかったことになる」系は死亡イベントではなく
致死ダメージの打ち消しで実装しているので、死亡画面は一瞬も出ない。
一度きりのチャージはプレイヤーの PDC に保存し、選び直しでリセットされる。

効果自身が与えるダメージ (反射・自傷) は `SyntheticDamage` を通し、
別の効果を誘発して連鎖しないようにしてある。

掛け直しは参加時・選択時・**リスポーン時**に行う。死亡すると attribute と飛行フラグが
落ちるため。

> **二段ジャンプ**はバニラに無いので、飛行フラグを借りて実装している。空中でジャンプを
> 押すと飛行の切り替えが飛んでくるので、それを打ち消して上向きの速度を与える。フラグは
> 着地するまで戻さないため、跳べるのは1回だけになる。クリエイティブとスペクテイターでは
> 飛行を奪わないよう何もしない。
>
> 飛行フラグには副作用がある。**バニラは「飛行を許されたプレイヤー」の落下ダメージを
> 丸ごと無効にする** (`Player#causeFallDamage` が `mayfly` で即 false を返す)。放っておくと
> 二段ジャンプを使わない限り落下ダメージが一切入らず、崖から歩いて降りても無傷になる。
> `setFlyingFallDamage(TriState.TRUE)` で明示的に戻している。クリエイティブへ移ったら
> `NOT_SET` に戻すので、そちらの飛行は痛くならない。

### 選択の確定

選択肢をクリックすると保存され、`onChosen` (よくばりの抽選) → 効果 → 無敵の解除 → 道具 →
ウェルカムギフトの順に処理されて画面が閉じる。**未選択のまま閉じられた
場合は開き直す** (`selection.force`)。閉じたままにできると効果無しで遊べてしまうため。

### ネームタグの下段

選んでいるモディファイアの名前を、他のプレイヤーから見たネームタグの下段に出す
(`NameTagDisplay`)。スコアボードの `below_name` 枠を使い、目標 `modifier_choice` の点数に
固定の文言 (`NumberFormat.fixed`) を指定してモディファイア名を出す。目標の表示名は空。
エンティティを増やさず、ネームタグと同じ条件 (距離・スニーク・可視性) で見える。

参加時・選択時・リスポーン時の掛け直し (`ModifierEffects#apply`) に合わせて更新し、
選択が無ければ点数ごと消す。メインのスコアボードは `scoreboard.dat` に残るので、
プラグインの停止時に目標ごと消す。自分のネームタグは自分には見えないので、自分の分は
出ない (`/m` で確かめる)。

### シェフの料理

料理の印は**アイテム側** (PDC `modifier:chef_buff`) に持たせてあり、`ModifierEffects#onConsume` が
選択に関係なく先に `ChefModifier#serve` を呼ぶ。つまりシェフの料理は誰が食べても同じ扱い。

**効果は食べたときに決まる。** `ChefModifier.EFFECT_PERCENT` (10%) で当たれば `EFFECTS` (良い 14 種 + 悪い 7 種)
から等確率に引き、外れれば何も起きない。結果はアクションバーに出る (良ければ緑、悪ければ赤)。効果は 8〜45 秒。
作った時点では何が出るか分からないので、料理の名前と説明は全部同じ。

- **作業台・手持ちのクラフト** — 完成品が食べ物なら、プレビュー (`PrepareItemCraftEvent`) の
  時点で印を付ける。効果は食べるまで決まらないので、まとめて作っても全部同じ料理として重なる。
- **かまど・燻製器** — 完成品スロットをクリックしたとき (`InventoryClickEvent`) に、取り出す前に
  付ける。シフトクリックでも数字キーでも付いたまま持ち物へ移る。焚き火は誰が焼いたか分から
  ないので対象外。ホッパーで抜いた分も対象外。

名前は翻訳キー (`Component.translatable`) で組むので、「パン」の部分はクライアントの言語で出る。

### フィッシャーズの宝釣り

宝釣りは釣り竿に**貸している**だけで、手から離れると外れる。`tick` (2 tick ごと) が持ち物を見て、
利き手かオフハンドにある釣り竿には最大レベルを付け、それ以外のスロットにある釣り竿からは外す。

付けるとき、元から付いていた宝釣りのレベル (無ければ 0) を印 (PDC `modifier:fishers_lent`) として
持たせ、外すときにそのレベルへ戻す。自前で最大レベルなら何もしないので、正規の宝釣り III は
印も付かず、そのまま残る。

持ち物の外へ出る経路では `tick` が追えないので、その場で外す。

- 捨てる (`onItemDrop`)
- インベントリでクリックする (`onInventoryClick`) — 箱へ移る前。まだ手にあれば次の tick で貸し直す
- 死んで落とす (`onDeath`)
- 効果を外す (`remove`) — 選び直し・退出・停止

耐久値は `PlayerItemDamageEvent` を釣り竿だけキャンセルして守る。シルバーフィッシュは
`PlayerFishEvent` の `CAUGHT_FISH` で 10% を引き、釣れたアイテムを消して、代わりに
シルバーフィッシュを同じ場所に湧かせ、バニラが魚に与えるのと同じ勢いで釣り人へ飛ばす。

### 採掘師

**鉱石の幸運。** 道具そのものは書き換えない。`BlockDropItemEvent` で、幸運 II を付けた**複製の道具**で
`BlockState#getDrops` を引き直し、落とし物の個数を差し替える。鉱石の落とし物は種類が変わらず
個数だけ増えるので、同じ種類の個数を置き換えれば済む (`MinerModifier.ORES` が対象で、
古代の残骸は幸運が効かないので入れていない)。

道具に幸運 II 以上が付いていればそのまま。シルクタッチなら鉱石そのものが落ちるので触らない。
素手や格下の道具で壊すと落とし物が無いので、そこも変わらない。

**食事の採掘速度上昇。** 食べ物の**満腹度回復量** (アイテムの `FOOD` コンポーネントの `nutrition`。
ステーキ 8、パン 5、リンゴ 4、クッキー 2) で決める。実際に回復した量ではないので、満腹でも同じ。
3 以下なら I を 10 秒、4〜7 なら I を 30 秒、8 以上なら II を 20 秒。ポーションや牛乳には無い。

**原木の遅さ。** `BLOCK_BREAK_SPEED` の attribute はブロックごとに効かせられないので、`tick` で
見ているブロック (`getTargetBlockExact`) を調べ、原木 (`MinerModifier.LOGS`、バニラの `#logs` と同じ顔ぶれ)
を向いている間だけ -50% を付け、外れたら外す。付いているかを見てから付けるので、向いている間に
attribute の更新が毎 tick 飛ぶことはない。

**作物。** `BlockDropItemEvent` で収穫物 (`CROP_YIELDS`) を落とし物から消し、種は残す。ジャガイモ・
ニンジン・ネザーウォート・カカオは収穫物が種を兼ねるので 1 個だけ残す (`SELF_SEEDING`)。青くなった
ジャガイモは種にならないので消す。スイートベリーは右クリック収穫 (`onHarvest`) で 1 個にする。
熟していない作物はもともと種しか落ちない。

### クリーパー保険

`interceptDeath` で、致死ダメージの加害者がクリーパー (`EntityDamageByEntityEvent#getDamager`) のときだけ
死を打ち消し、冷笑と同じく HP を半分に戻してリスポーン地点へ飛ばす。TNT や殴られた死は対象外。
冷笑のような一度きりのチャージではなく、**3 分のクールタイム** (サーバーの tick で数え、メモリに持つ)。
再起動すれば新品に戻る。

### よくばり

選ぶと `onChosen` で他のモディファイアから **2 つ**を重み付きで引き (よくばり自身は母集団に入れない)、
id を選択と一緒に PDC (`modifier:bundle`) へ保存する。効果を配るときは `Modifier#resolveFor` が
その 2 つを束ねた `ModifierBundle` を返し、`ModifierEffects` はそれを普通のモディファイアとして扱う。
常時効果もフックも中身の両方へ順に配り、死を打ち消すものはどれか 1 つが打ち消した時点で止める。

- 名前とアイコンと重みはよくばりのもの。ネームタグの下段も「よくばり」
- `/m` と選択画面の説明には、中身の名前と説明が並ぶ
- 道具は中身のぶんを両方もらえる
- 一度きりのチャージはプレイヤーごとに 1 つなので、冷笑と死神ルーレットを両方引いても助かるのは 1 回
- 中身の効果は独立に動くので、農奴と採掘師のように同じ落とし物を触るものは順番どおりに重なる

### 選んでいる間の守り

夜に参加すると、選択画面を見ている間に敵モブに殺される。**スペクテイターにはできない**。
バニラは観戦者のインベントリのクリックをサーバー側で捨てるので、選択肢を押せなくなる。
代わりに `SelectionGuard` が **無敵 (`setInvulnerable`)** にする。

- 参加して選択が要る時点で守り始める (パックの適用を待つ間も含む)。`/m select` で開き直すときも
- 確定した時点でやめる。退出時もやめる (無敵のまま保存させない)
- 守っている印 (PDC `modifier:guarded`) を残し、守っている最中にサーバーが落ちて印が残っていたら、
  次の参加時 (選択済みなら) に外す
- 守る前の状態は覚えない。`Player#isInvulnerable()` はフラグではなく「今ダメージが通るか」を答え、
  参加直後はクライアントの読み込み待ちで必ず true になる。それを覚えて戻すと永久に無敵になる
  (E2E で実際に踏んだ)。管理者が手で付けた無敵は、選び終わると外れる

> **26.1 と 26.2 で戻り型が違う API に注意。** `EntityPotionEffectEvent#getEntity()` は 26.2 で
> `LivingEntity` を返すようになった。26.2 でコンパイルした呼び出しは 26.1 で `NoSuchMethodError`
> になる (E2E サーバーは 26.1)。`EntityEvent` にキャストして呼ぶと両方で動く。

### 熱血お肉屋さんの肉とアレルギー

- **落とし物** — `onKillDrops` で、倒したのが `Animals` なら肉 (`ButcherModifier.COOKED` の生・焼き) を
  焼いた肉に替えて 1 個足す。燃えて焼けていた肉にも足す。革や羽は触らない。
- **腐った肉** — 食べ物由来のポーション効果は `EntityPotionEffectEvent` に `Cause.FOOD` で来る。
  食べ終わった直後に同じ tick で付くので、`onConsume` で「直前に食べた物」を覚えておき、それが
  腐った肉なら空腹だけ止める。生の鶏肉の空腹はそのまま。
- **アレルギー** — `onConsume` で、食べ物 (`isEdible`) のうち `MEATS` に無いものを食べたら空腹・吐き気を付け、
  20% で毒 II (5秒) も付ける。肉は生・焼き・魚・腐った肉・ウサギシチュー。ポーションや牛乳は食べ物ではない。

### 死神ルーレットの効果音

発動時、助かった側と巻き込まれた側の両方に `modifier:reaper_roulette` を鳴らす
(`ReaperRouletteModifier.SOUND`)。音声はリソースパックの `sounds/reaper_roulette.ogg` で、
`sounds.json` に同名で登録してある。パックを適用していないクライアントでは何も鳴らない。
`PackAssetsTest` が音声と登録の両方を見張っている。

## リソースパック

`pack/` がそのままリソースパックになっている。`pack_format` は 26.2 のサーバー jar の
`version.json` にある `resource_major` (= 88) に合わせてある。

```
pack/
├── pack.mcmeta
└── assets/modifier/
    ├── items/choice/<id>.json     # item_model の指す先
    ├── models/item/<id>.json
    ├── textures/item/<id>.png     # 128x128
    ├── sounds.json                # 効果音の登録 (死神ルーレット)
    └── sounds/reaper_roulette.ogg # 発動時に鳴らす。mono の Ogg Vorbis
```

### 参加者への配布

Minecraft のリソースパックは、サーバーがファイルを送るのではなく**クライアントが URL へ
取りに来る**。そのため以下の構成にしてある。

1. `gradle :plugin:build` が `pack/` を zip にしてプラグインの jar へ同梱する
2. 起動時にプラグインが小さな HTTP サーバーを立て、その zip だけを配る
3. 参加時に URL と SHA-1 をクライアントへ送る

SHA-1 は zip の中身から計算するので、パックを直しても手当ては要らない。URL にはハッシュの
先頭が入るため、古い zip がキャッシュで返ることもない。

> 同じサーバーの [Mamble](../mamble) もパックを持つ。**2 つを別々に push すると、クライアントは先のパックの
> 確認を破棄 (DISCARDED) してしまう** (1 回の要求に束ねても同じ)。そこで `resourcePackZip` が隣の
> `../mamble/pack` を見つけたら自分の zip に取り込み、**1 つのパックとして送る**。Mamble は Modifier が居ると
> 自分では送らない。`ResourcePackService#send` は `ServicesManager` に登録された他のパックも束ねられるが、
> 今はどのプラグインも登録しない。選択画面を開く判断は自分のパックの状態だけを見る。

> **公開サーバーで使う場合は `resource-pack.host` を必ず変えること。**
> 既定の `127.0.0.1` は同じマシンのクライアントからしか届かない。
> `resource-pack.port` (既定 8123) も Minecraft 本体とは別に開ける必要がある。

選択画面は、パックの適用が決着してから開く。`resource-pack.apply-timeout-ticks` を過ぎたら
待たずに開くので、パックが降ってこなくても参加者が固まることはない。

### アイコンが出ないときの切り分け

`/modifier status` が配信 URL・SHA-1 と、モディファイアごとの重み・`item_model` キーを出す。
コンソールからも実行できる。

```
[Modifier] パック: http://127.0.0.1:8123/modifier-af22587d2115.zip (sha1 af22587d2115…, 126726 bytes)
[Modifier] - fat 重み 9/100 → modifier:choice/fat (土台 minecraft:bread)
```

ここまで出ていればサーバー側は正しい。あとは URL がクライアントから届くかどうかで、
届いていなければ土台アイテム (パン等) の見た目で表示され、ログに警告が出る。

### 通し検証 (`e2e/`)

`bot/scenario.cjs` が実際に参加し、観測を1行1件の JSON で流す。成否の判断は JUnit 側。
サーバーを2つ順に立てるので、クラスも2つに分かれている。

#### `SelectionE2eTest` — 参加からモディファイア確定まで

1. 本番の jar が読み込まれ、24種が登録され、パックの配信が始まる
2. 参加 → パック配布 → 選択画面 (スロット 11/13/15 に1つずつ) → 閉じたら開き直す → クリックで確定
   → 確定後は開き直さない
3. **3人が同時に参加**して、それぞれ確定できる
4. **選んだ効果が実際に乗る** — デブを引き当てて 8 ダメージを与え、25% 減って 6 になること
5. 選択済みなら入り直しても画面が出ず、`/modifier select` で選び直せる
6. **シールドバッシュが実ゲームで反射する** — 非推奨系統の `DamageModifier.BLOCKING` が
   26.x でも値を持つことの確認
7. 二段ジャンプが上向きの速度を生む
8. **スウィフトネスブーツでも落下ダメージが消えない** — 飛行フラグを借りている副作用の確認
9. **不眠症が夜明けで移動速度低下を付ける** — `TimeSkipEvent` の時点で寝ている判定に
   なっていることの確認
10. サーバー側に例外が出ていない
11. 下準備のコンソールコマンドが黙って失敗していない

> **7 はボットの位置ではなく、サーバーが送ってくる速度で見ている。** mineflayer は
> 自分の位置をクライアント側で予測していて、**自分あての `entity_velocity` を取り込まない**。
> そのためサーバーが上向きの速度を与えても、ボットの座標は落下したままになる。長らく
> 「プラグインが動かないのか、ボットが入力を作れないだけなのか」を切り分けられずにいたが、
> パケットを覗くと `velocity.y` に `JUMP_UP` (0.62) が乗っていた。効果そのものは実サーバーで
> 働いている。
>
> トグルは**滞空中**に送らないと発動条件から外れる。固定の待ち時間にすると普通のジャンプの
> 往復 (約 0.6 秒) と競り合って着地後に送ってしまうので、落下に転じたことを確かめてから送る。
> 送れていたかは観測の `airborne` に出るので、速度より先にそちらで落とす。

#### `WorldResetE2eTest` — wiah との噛み合わせ

**wiah プラグインも同じサーバーに載せて**、死亡とワールドリセットが繋がるかを見る。
この2つは別のイベントで動く — Modifier は致死ダメージを `EntityDamageEvent` で打ち消し、
wiah は `PlayerDeathEvent` でリセットを起動する。打ち消された死では死亡イベントが
そもそも生まれないので、リセットも走らない。

冷笑は一度だけ死を打ち消すので、同じプレイヤーが2回死ねば前半と後半で結果が変わる。

1. 冷笑を引き当てて2回死ぬ
2. **打ち消された1回目ではリセットが走らない** (ログも予約ファイルも出ない)
3. 打ち消された側は HP が最大値の半分で立ち上がる
4. **チャージを使い切った2回目ではリセットが走る** — 予約ファイルに削除対象が載る
5. 全員キック → サーバー停止まで進む
6. 2つ載せてもサーバー側に例外が出ない
7. 下準備のコンソールコマンドが黙って失敗していない

> このテストは**サーバーを落として終わる**ので、`SelectionE2eTest` とはサーバーを分けてある。
> 向こうの検証中に誰かが死ぬと、そこでサーバーが消えてしまうため。
>
> wiah は別リポジトリ (`../world_is_also_hardcore`) なので、`buildWiah` タスクが
> ビルドを試み、jar が見つからなければ**このクラスだけ skip する** (理由はビルドログに出す)。
> 場所は `-Pmodifier.wiahDir=...` で差せる。


### テストサーバーだけ 26.1 なこと

ヘッドレスクライアント (`minecraft-protocol`) が **26.1 までしか対応していない**ため、
テストサーバーには 26.1 を使う。**プラグインは本番と同じ成果物** (26.2 でコンパイルした
jar) をそのまま載せる — 使っている API は両バージョンに存在することを確認済みで、実際に
26.1 のサーバーで例外なく動く。

| | 本番 | E2E |
| --- | --- | --- |
| Minecraft | 26.2 | 26.1.2 |
| プラグイン | 同じ jar | 同じ jar |
| ポート | 25565 / 8123 | 25566 / 8124 (リセット検証は 25567 / 8125) |
| `online-mode` | `true` | `false` (ボットが参加するため) |

ポートをずらしてあるので、**開発サーバーを起動したままテストを回せる**。テスト用サーバーは
`e2e/build/server` と `e2e/build/server-reset` に毎回作り直され、`run/` には触らない。
26.1 の jar は SHA-256 を検証して自動取得・キャッシュする。

> 26.2 で入った硫黄・辰砂まわりは 26.1 に無い。**「26.2 でだけ壊れる」類の不具合は
> この E2E では捕まらない**。

#### 26.x で gamerule 名が変わっていること

**gamerule の名前は camelCase から snake_case になり、いくつかは改名もされている。**
旧名を送ってもコンソールに `Incorrect argument for command` が出るだけで、テストは
そのまま進んでしまう。下準備が黙って効いていない状態になるので注意。

| 旧 | 新 |
| --- | --- |
| `naturalRegeneration` | `natural_health_regeneration` |
| `playersSleepingPercentage` | `players_sleeping_percentage` |
| `keepInventory` | `keep_inventory` |

`org.bukkit.GameRule` の定数名を見ると、改名されたものは新旧が対になって残っている
